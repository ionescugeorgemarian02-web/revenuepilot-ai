CUM SE FOLOSEȘTE ACEST PLAN

Acest document este partenerul meta-promptului „REVENUEPILOT AI — META-PROMPT MASTER V3”. Utilizatorul
atașează AMBELE documente la prima sesiune Codex. În PASUL 00, Codex trebuie să creeze repository GitHub NOU și
să insereze acolo conținutul ambelor, păstrând un registru canonic de progres. Din acel moment, fiecare sesiune
Codex/Claude citește direct repository-ul nou.

IMPORTANT: GitHub = repository de cod, plan, dovezi și colaborare. Nu este hostingul aplicației dinamice și nici baza
de date de producție. În acest moment NU există host pregătit și NU există chei API comerciale Claude/OpenAI/Gemini
pentru backend. Nu confunda abonamentele cu API-uri. Nu atinge repository-ul „fabrica-autonoma”. Nu instala servicii
plătite, nu cere sudo. Fiecare integrare reală se activează numai după verificarea accesului și aprobarea
proprietarului.

MOD DE OPERARE PRINCIPAL: un singur pas executat per sesiune, urmat de STOP. Utilizatorul poate face switch
manual între Codex și Claude. Nicio sesiune nu se bazează pe memoria conversației anterioare: se citește planul și
starea din Git.


PALETE RECOMANDATE DE MODELE (VERIFICATE PUBLIC, NU CONFIRMATE ÎN CONTUL TĂU)

H = risc strategic înalt: Codex GPT-6 Astra / High (Claude Opus 5.5 / High). Folosește rar, la arhitectură, securitate,
multi-tenancy, audit și decizii greu reversibile.

M+ = implementare foarte dificilă: Codex GPT-6.1 Sol / High (Claude Opus 5.5 / Medium-High).

M = implementare serioasă, raționament echilibrat: Codex GPT-6.1 Sol / Medium (Claude Sonnet 5.5 / Medium).

T = UI, integrare clară, cod cu scop delimitat: Codex GPT-6.1 Terra / Medium (Claude Sonnet 5.5 / Medium).

L = extrageri, documentare, corecții mecanice: Codex GPT-6 Luna / Low (Claude Haiku 5.5 / Low).

Modelul disponibil în SELECTOR are prioritate; nu pretinde că promptul poate schimba modelul automat. În Claude
Code, /model arată lista reală. La Codex, lista și nivelurile diferă în funcție de plan, rollout și workspace.


RESPONSABILITĂȚI CLAUDE/CODEX

- Orice pas poate fi EXECUTAT de oricare dintre cele două familii, dacă modelul și instrumentele sunt disponibile.

- Review-urile critice sunt independente: dacă Codex a scris, Claude revizuiește; dacă Claude a scris, Codex

automat.

CRITERII TRANSVERSALE DE ACCEPTARE (PENTRU FIECARE PAS)

A. Sursa Git: commit cu scop limitat; istoricul păstrat; branch sau PR identificabil; worktree fără schimbări
nereconciliate.

B. Dovezi: cerința, implementarea, metoda de test, rezultate, known limitations, costuri/dependențe și reviewer.

C. Calitate: verificări deterministe relevante; fără regresii demonstrate; orice problemă de securitate blocantă este
rezolvată sau pasul rămâne blocat.

D. Învățare: la finalul oricărui pas, inclusiv FAILED, înregistrează observația și ipoteza de îmbunătățire. Lecțiile nu
devin automat reguli globale fără evaluări.

E. Cost: nu adăuga servicii plătite; nu invoca API-uri fără chei; nu rula sute de apeluri/agenți pentru un singur test.
Maximum o sarcină mare în această sesiune.

F. Handoff: status compact și verificabil pentru modelul următor. Utilizează git ca sursă de adevăr, nu contextul
conversației.

G. Security: niciun secret, token, cookie, date personale ori asset comercial confidențial în Git; datele de test sunt
sintetice.

MATRICEA DE GATES TRANSVERSALE PENTRU REVENUEPILOT AI



G0 — GIT/PROVENANCE: repository nou, branch unic, commit, schimbări auditate, fără secrete.

G1 — CONTRACT: input/output validat, identitate tenant și permisiuni, acceptance test clar.

G2 — BUILD/STATIC: lint, types, build, dependențe verificate, scanare de secrete dacă instrumentele permit.

G3 — TEST: unit/property/integration/UI/E2E relevant, cu mock/live separat și log de rezultat.

G4 — SECURITY/PRIVACY: limitare acces, cross-tenant, auth, consent, PII redaction, attack surfaces.

G5 — REVIEW: evaluator independent pentru pasul critic; constatări specifice, verificabile și în scope.

G6 — LEARNING: episod/lecție cu cauza, probă, baseline, test, propunere de calibrare și limitare.

G7 — BUSINESS: cost, efect asupra valorii, fără costuri noi neaprobate, funcționalitate folosită real.

G8 — RELEASE/AUTONOMY: niciun efect extern fără acces real, audit, approvals și rollback.

Aceste porți sunt IMPLEMENTATE PROGRESIV. În PASUL 00 nu pretinde că există G0–G8 toate. Pentru fiecare, ține un
status NOT_IMPLEMENTED / IMPLEMENTED / VERIFIED / BLOCKED.



CALIBRAREA AGENȚILOR ȘI A EVALUATORILOR



Pentru FIECARE agent real sau rol logic, menține:

- identitate și versiune; scop; model/abonament; tool permissions; context scope; input/output contracts; cost/latency
budgets;

- parametri controlați: praguri de severitate, risc, escaladare, repetiție, confidence, temperatură doar când modelul o
expune, context length, top-k retrieval, memory TTL, review sampling, retries, expiration, capability access;

factual errors, originality, latency, token usage, cost, manual minutes, downstream outcome;

etichetate uman;

- buclă de învățare: eveniment → clasificare → lecție propusă → test de reproducere → nouă variantă → baseline vs
candidate → holdout → aprobare → canary → rollback → documentare;

accessibility; channel fit; copyright; conversion intent; measured outcome. Scorurile sunt ordinale până când există
